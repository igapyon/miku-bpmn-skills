## 見直し結果と適用上の注意

候補の境界は、commit 済み変更、Draft PR、merge commit、公開 Release、次 work branch という別々の handoff と完了条件に合わせました。小さな版数更新や bundle 確認は C01 の中にまとめ、人による review / merge と Release 公開は異なる出力を作るため別 Process にしています。

E08 の GitHub 操作は利用者の報告であり、E09 は PR #8 の merge を SCM が検証した結果です。remote tag ref は E10 で独立確認しましたが、GitHub Release page や添付 ZIP の存在・内容は API で検証していません。この実例では Release を公開してから pull しました。タグ作成と pull の順序は案件に応じて選べます。

会話を照合すると、最初の push（E05–E06）は利用者が commit を依頼したターンで先行して実行されました。利用者が続けて送った明示的な push 依頼では、ローカルの `-done` ブランチを確認して再実行を見送りました（E07）。pull（E09）は利用者から GitHub 操作の報告（E08）を受けた時点で実行しました。再利用時に必要な依頼と、v0.4.4 の実行後に整理した GitHub 操作の案内方法は、[現在の親 Process](../../bpmn/P00002/P0002-00000.md#github-操作の案内) に示します。
