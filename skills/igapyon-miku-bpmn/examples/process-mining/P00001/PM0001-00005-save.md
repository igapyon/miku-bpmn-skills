# PM0001-00005 — 採用した候補から Process を定義する

## プロンプト

利用者が定義化を求めた候補や、定義として採用した候補から、再利用するための定義を作ってください。

- 4 の候補のレビュー結果と利用者の判断 `{{review}}`
- 利用者が指定した作業先、出力形式、既存定義 `{{delivery}}`
- 親 Process を求められた場合の目的、子 Process の選択と呼び出し順 `{{parent_request}}`

1. 依頼に含まれる定義を特定し、保存先と既存ファイルを確認してください。決められない点がある場合は必要な指定を尋ねます。親の作成が依頼に含まれる場合は、子 Process の選択と順序を使い、呼び出しごとに Call Activity を置いて Sequence Flow でつなぎます。目的、順序、参照先、入力元、渡す出力、未解決の入力を提示してください。元の activity の順序をそのまま利用者の指定として使わないでください。組み立てだけの依頼ではこの提示が成果です。
   - 親を組み立てるときは、各呼び出しの必須入力が親への外部入力か、その時点までに完了する呼び出しの出力から得られるかを確認してください。後続の出力しか供給元がない、または供給元が未指定のときは、指定順を維持したプレビューに不足入力を示します。外部入力で用意するか呼び出し順を見直すかを利用者に確認し、供給元が確定したら親の定義を保存してください。保存条件を満たす子の定義は先に保存できます。
2. 保存する定義は、指定がなければ 1 Process に 1 Markdown ファイルとし、目的、開始条件と入力、タスクごとの指示と判断、出力、完了条件を記載してください。新規に P00001 の同梱例と同じ構成を使う場合は、各ファイルに BPMN XML を含め、親を `P0001-00000.md`、子を `P0001-00001.md` 以降にします。ファイル名の拡張子を除いた値を Process ID にしてください。既存定義を更新するときは Process ID とタスク ID を維持してください。
3. BPMN XML を含める場合は、各ファイルにその Process の `xml` コードブロックを一つ置き、本文の実行指示を対応するタスク ID で示してください。開始と終了を置き、合意した順序を Sequence Flow にします。人の判断や回答を待つ工程には User Task を使い、本文に質問、期待する回答、再開条件を書きます。必要な分岐の条件や接続が確定できなければ、その箇所をレビューへ戻してください。実行エンジンで使うことを前提としない例示モデルでは `isExecutable="false"` とします。
4. 同梱例の形式で親と子を別ファイルにする場合は、親側の `bpmn:import` に子の名前空間、`importType`、`location` を指定してください。`location` には子の XML を書き出したときの相対パス（同じ場所へ書き出すなら `P0001-00001.bpmn` など）を指定します。Call Activity の `calledElement` で子の名前空間と Process ID を参照します。本文からは各子の Markdown へ相対リンクを張り、どの出力をどの入力に渡すかを親の本文に記載してください。案件固有の値は、必要に応じて定義中の入力と対応する適用例に記載します。
5. 保存前に、リンク先と必要な入力の供給元を確認してください。XML がある場合は、構文、本文との工程順や判断の一致、ID の重複、Sequence Flow の両端、呼び出し先の名前空間と ID を確認します。BPMN の XSD を利用できる場合は、コードブロックから抽出した XML を照合し、必須属性の不足や、要素に使えない属性がないか確かめてください。整合が取れた定義を、依頼された範囲で保存してください。daybook とプロジェクトが別なら、根拠の参照は会話で示し、保存先へのリンクは daybook 側に記録します。プロジェクト側に daybook の内部リンクやパスを載せないでください。

### 出力

定義を保存した場合は、保存したファイルと候補 ID の対応、未決の入力、行った確認の範囲を返してください。XML の構文と参照、BPMN の XSD、実行エンジンでの動作のうち、どこまで確認したかを報告してください。
