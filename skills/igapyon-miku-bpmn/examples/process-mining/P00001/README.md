# P00001 — Activity から再利用できる Process を見つける

miku-daybook の activity から実際の作業の流れを読み、別の仕事で使える Process を見つけるためのプロンプト例です。題材は Agent Skill の新規作成です。読み取った事実を利用者が確認できる状態にしてから、採用された候補を定義にします。

## 使い方

最初に、対象の activity と「どの仕事を再利用したいか」を渡します。関連 task があれば加えます。AI にこのディレクトリのファイルを順に読ませるか、各ファイルの「プロンプト」をコピーして使ってください。入力欄の `{{...}}` には利用者の指定や前段の出力を入れます。同じ会話で使う場合は、その会話にある出力を参照できます。

| プロンプト | 受け取るもの | 次に渡すもの |
| --- | --- | --- |
| [1. 対象範囲を決める](PM0001-00001-scope.md) | 利用者の依頼、activity、関連 task（任意） | 対象範囲と記録一覧 |
| [2. 記録から出来事を拾う](PM0001-00002-evidence.md) | 対象範囲と記録一覧、activity 本文 | 根拠表と出来事の前後関係 |
| [3. 再利用できる候補を見つける](PM0001-00003-discover.md) | 対象範囲と記録一覧、根拠表と前後関係 | Process 候補一覧 |
| [4. 根拠を照合して候補を提示する](PM0001-00004-review.md) | 対象範囲と記録一覧、根拠表と前後関係、Process 候補一覧、原記録 | 候補のレビュー結果と利用者の判断 |
| [5. Process を定義する](PM0001-00005-save.md) | レビュー結果と利用者の判断、作業先と形式の指定 | Process 定義、依頼に応じた親 Process の案 |

発見の依頼は、根拠と確認したい点を添えて候補を提示するところまでです。「この候補を定義にして」など、利用者が定義化を求めたときや、定義として採用したときに 5 へ進みます。親 Process が必要なときは、利用者が選んだ定義と呼び出し順を使います。成果物の形は [親 Process と子 Process の同梱例](../../bpmn/P00001/P0001-00000.md) を参照してください。

## この題材に適用する場合

入力は 2026-11-27 の「生成AIを使った作業手順の仕様検討」です。構想の相談から、レビューで指摘した手順を SKILL.md に反映するまでを対象にします。この区間の中でも、別セッションでの再開はレビューと修正の間にあった作業事情として扱えます。版の更新や配布の検討、同梱例の編集、別題材での机上シミュレーションは、発見対象の区間より後です。

| activity の記述 | 読み取れること | 候補にするときの扱い |
| --- | --- | --- |
| 「Agent Skills の命名候補」と「miku-bpmn-skills リポジトリの作成」 | `miku-bpmn` は命名の節では候補。その後、利用者がその名前に対応するリポジトリを作成して clone した。 | 構想と命名をまとめられる。名前を確定した会話の文面や時点は不明。命名を確認する User Task を設けるなら、再利用時の手順案として示す。 |
| 「Agent Skill の初稿を作成」と「リポジトリ内に合意事項と未決定事項を明記」 | 利用者が用意した作業先で、AI が README、SKILL、TODO を整えた。 | 初稿を作る候補では、作業先を利用者から受け取る入力にできる。実際の名前や未決事項は題材の値として扱う。 |
| 「初稿の自己レビュー」と「親の Process の組み立てと提示を反映」 | README の構想に対応する手順が SKILL に足りないと分かり、後の作業で追加された。通し検証は未実施。 | 初稿をレビューして修正する候補になる。代表シナリオを使った確認は、今後の手順への追加案として扱える。 |

この表は activity の読み方を示す作業例です。候補の件数や工程名はプロンプトに固定していません。同梱の BPMN 定義は、当時の activity をもとに別途作成した参照例です。プロンプトを使うときは、発見とレビューを元の記録から進め、定義化で必要になった段階で成果物の形式を参照してください。

## シミュレーションで確認した範囲

上の activity から3つの Process 候補を発見し、仮の利用者回答を与えて、親1件と子3件の Markdown を一時ディレクトリへ書き出しました。XML は4件とも ID、工程順、本文との対応、参照先を確認し、[OMG が公開する BPMN 2.0.2 の XSD](https://www.omg.org/spec/BPMN/2.0.2/About-BPMN/#specification-documents) で検証しました。

候補提示のみ、一部の候補だけを採用、必要な入力を受け取れない呼び出し順の3条件も机上で確認しました。これらは1件の activity を対象にした確認です。他の activity や BPMN 実行エンジンでの動作は未確認です。
