# PM0001-00004 — 根拠を照合して候補を提示する

## プロンプト

候補一覧を activity の該当箇所と照合し、利用者がどの候補を使うか判断できるようにしてください。

- 1 の対象範囲と記録一覧 `{{scope}}`
- 2 の根拠表と出来事の前後関係 `{{evidence}}`
- 3 の Process 候補一覧 `{{candidates}}`
- 原記録またはその参照 `{{activities}}`
- 利用者の回答（すでにある場合） `{{user_decisions}}`

1. 候補から根拠表、根拠表から原記録へ戻り、タスクの内容、主体、順序、判断と結果を照合してください。原記録から候補への逆向きの確認も行い、利用者の判断や受け渡し、修正が理由なく落ちていないか見てください。同一の activity にある別の仕事が混ざっていないかも確認します。
2. 根拠表に抜けや誤分類があれば 2 の該当箇所を直し、工程の分け方や完了条件に無理があれば 3 の該当候補を見直してください。根拠が読めない、または解釈が一つに定まらないときは、分かる範囲と残る問いを示してください。
3. 利用者に、候補 ID と名前、目的、主要な入力と出力、根拠への参照、採用で意味が変わる推定や追加案を提示してください。質問は利用者の回答が必要な点に絞ります。候補の採用、修正、保留、見送りを受け付けます。すでにその判断が示されていれば、回答を適用してください。
4. 利用者が候補の定義化を求めるか、候補を定義として採用したら、その候補と、採用された追加案だけを 5 に渡してください。追加案を保留しても定義が成立する場合は、合意した範囲で進めます。必須の判断が残る候補は、その点と再開条件を示します。根拠が足りず候補を提示できない場合は、不足している記録や判断を返してください。
5. 利用者が新しい手順を加えた場合は、その判断をモデルに反映し、元の記録に基づく説明も保ってください。親 Process の依頼もある場合は、既に指定された呼び出し順を渡し、不明な選択や順序を確認してください。

### 出力

**候補のレビュー結果と利用者の判断**として、提示した候補と根拠、修正点、未決の確認事項を返してください。回答がある候補は判断の内容を記し、回答が必要な候補は回答待ちとします。定義化する候補があれば、確定したタスク、入出力、完了条件をその候補 ID とともに渡してください。
