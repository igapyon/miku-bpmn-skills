# P0002-00002 Draft PR を公開する

## 目的と入力

committed change set を `igapyon-miku-scm` の固定手順で公開し、根拠に基づく Draft PR を作ります。入力は `{{repository_root}}`、作業ブランチ、commit SHA、変更の目的、リモート、base ブランチです。利用者からこのリポジトリの `miku-scm sync push` の実行依頼を受けて開始します。commit の完了後に依頼を待っている場合は、ここで一旦止まります。

## 手順と判断

1. `P0002-00002-task-01` で `repository.sync.push.prepare --apply` を行い、status が `prepared` の場合だけ進みます。結果から operation ID、plan digest、base、HEAD、evidence、suggested draft path を保持します。already-published や blocked の結果から別の apply を組み立てません。
2. `P0002-00002-task-02` で保存済み evidence と writing contract だけを使って PR title と本文を一度作ります。差分と依頼目的を説明し、commit message から意図を推測したり、未確認の test / effect を加えたりしません。結果を suggested draft path に保存します。
3. `P0002-00002-task-03` で読み取り専用の `repository.sync.push.draft.prepare` に `--repo`、`--operation`、`--expected-plan-sha256` を渡します。runner は検証済みの計画から draft path を取得します。`draft-ready` として返された公開用ワークフローと引数列をそのまま保持します。
4. `P0002-00002-task-04` で返された `repository.sync.push.apply` と arguments を一度だけ実行します。push の確認、PR の repository / branch / base、PR 番号と open / draft 状態、local branch、backup を記録します。不確かな remote write は再送せず、saved receipt に従って調査します。

記録例では通常 commit は skip され、1 commit が新しい HEAD `3433565` にまとめられました。Draft PR #8 が作成され、push の比較は `0 0`、local branch は `-done` に移りました。

## 出力と完了条件

Draft PR の URL、公開ブランチ、head SHA、base ブランチを P0002-00003 へ渡します。ローカルの `-done` ブランチは P0002-00005 で使います。操作記録とバックアップの参照を利用者に返します。remote push が確認され、exact Draft PR が作成または検証されたら完了です。`-done` branch 上の再依頼は再公開せず、通常の human review へ渡します。
