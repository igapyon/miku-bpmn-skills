# P0002-00001 版数付き変更を準備して commit する

## 目的と入力

利用者が指定した変更と版数更新指定から、規約に沿う版数付き変更を作り、commit します。入力は `{{repository_root}}`、work branch、既存変更 `{{pending_changes}}`、`{{version_increment}}`、`{{version_policy}}`、版数の正本と関連する版数参照、タグの規約、配布 ZIP のビルド手順です。

    <bpmn:task id="P0002-00001-task-03" name="authoritative file と関連参照を更新する"/>

## 手順と判断

1. `P0002-00001-task-01` で対象 repository、active work branch、既存の変更、authoritative version file、更新規約、build 手順を読みます。開始時に存在する変更は利用者の依頼範囲と整合するかを確認します。
2. `P0002-00001-task-02` で、指定された increment を repository の版数 policy に当てはめ、`igapyon-miku-scm` の読み取り専用ワークフロー `version.increment.validate` に対象リポジトリ、版数の正本、版数規約、更新の種類を渡して候補を確認します。候補を確定できない場合は変更せず停止します。記録例では `a.b.c++` を SemVer patch として検証し、`0.4.1` から `0.4.2` を得ました。
3. `P0002-00001-task-03` で authoritative file と明示された関連版数参照だけを更新します。記録例では `package.json`、README、TODO を更新しました。
4. `P0002-00001-task-04` で指定 build command を実行し、生成物の存在と内容を確認します。記録例では ZIP の一覧と SHA-256 を確認しました。
5. `P0002-00001-task-05` で変更一覧と差分を確認し、`git diff --check` を行います。利用者の `miku-scm git add commit` の依頼を受け、`igapyon-miku-scm` の `work.commit` で対象リポジトリの変更をコミットします。commit 結果、対象 paths、HEAD、作業ツリー状態を記録します。

## 出力と完了条件

commit SHA を P0002-00002 に、確認済みの版とタグの規約を P0002-00004 に渡します。ローカルで生成した配布 ZIP とその確認結果は利用者に返します。版数の検証、ZIP の生成と確認、commit が成功したら完了です。記録例の commit は `4d9dbda`、bundle は `igapyon-miku-bpmn-skills-0.4.2.zip` です。
