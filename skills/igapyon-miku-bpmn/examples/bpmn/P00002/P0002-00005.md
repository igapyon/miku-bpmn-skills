# P0002-00005 merge を検証して次の work branch を作る

## 目的と入力

frozen `-done` branch に対応する PR の merge を確認し、shared base から次の work branch を開始します。入力は `{{repository_root}}`、`{{done_branch}}`、公開ブランチと head SHA、対象 PR、base ブランチです。確認済みの merge commit SHA があれば照合に使います。マージ後に、利用者からこのリポジトリの `miku-scm sync pull` の実行依頼を受けて開始します。マージや Release 公開の報告を受けて依頼を待っている場合は、ここで一旦止まります。

## 手順と判断

`P0002-00005-task-01` では `igapyon-miku-scm` の `repository.sync.pull` を、対象リポジトリを `--repo` で指定し `--apply` を付けて実行します。runner が対象 PR のマージを検証し、取得した base から次の作業ブランチを作成したことを確かめます。runner が示す PR、head SHA、base ブランチを入力と照合し、merge commit SHA を記録します。事前に SHA が確認できている場合は一致も確かめます。マージを確認できない場合や照合結果が異なる場合は、runner の結果を利用者に伝え、この工程を保留します。

タグは merge 後、作業の都合に合わせて `sync pull` の前後どちらで作成しても構いません。タグの確認が必要で対象名が分かっている場合は、`git ls-remote --tags` などで参照先を読み取り専用で確認できます。タグの有無、参照先の相違、照会できなかったことは、その時点の結果として記録します。

記録例では sync pull が PR #8 を検証し、branch `devel-tiga1128hed` を `origin/devel` から作りました。runner の tag status は unresolved だったため remote `v0.4.2` tag ref を読み取り専用で確認しました。local tag がないことだけから remote tag の欠落を推定しません。

## 出力と完了条件

検証済み PR merge、shared base SHA、次 work branch、backup、stash の有無を利用者に返します。作業ツリーが clean で、次 branch が期待する base を追跡していることを確認したら完了です。タグを確認した場合は、その結果を添えます。
