# P0002-00004 GitHub Release を作成して公開する

## 目的と入力

review 済み変更の version tag に対応する GitHub Release を人が作成し、公開します。入力は確認済みの `{{version}}`、リポジトリのタグ規約、対象 PR とその公開ブランチ・head SHA・base、人が確認したマージ結果、操作を担当する利用者です。

## 手順と判断

1. User Task `P0002-00004-task-01` で人が GitHub の Tags から Draft a new release を選びます。`{{version}}` とタグの規約からタグ名を決め、対象 PR のマージコミットをタグの参照先に指定します。対象が判断できない場合は、公開を保留してその時点の状況を報告します。Release notes を用意する場合は、対象 PR の差分に沿っているかを確認します。記録例では利用者が新しいタグに `v0.4.2` を指定したと報告しました。
2. User Task `P0002-00004-task-02` で人が Publish release を操作し、表示された Release の公開を確認します。親 Process で一括案内を受けた場合は、PR の操作と合わせて一度だけ結果を報告します。一操作ずつ進めている場合は、この操作の結果を報告します。
3. `P0002-00003-task-04` で AI が GitHub の PR 詳細を読み取り専用で参照し、対象リポジトリ、PR、公開ブランチ、head SHA、base、マージ済みの状態と merge commit SHA を照合します。この Task の ID は、マージ照合を工程3から移した際に引き継いでいます。
4. `P0002-00004-task-03` で AI が remote のタグが確認済みの merge commit SHA を指し、同じタグの GitHub Release が公開済みであることを確認します。照合に必要な情報が得られない場合や結果が一致しない場合は、結果を示して後続工程を保留します。配布 ZIP の添付も確認した場合はその結果を記録します。利用者が報告した操作とツールで確認した結果はそれぞれ記録します。

## 出力と完了条件

マージと Release を照合できたら、確認済みの PR と merge commit SHA を P0002-00005 に渡します。タグ名と Release の参照を親 Process の出力に記録します。
