# P0002-00004 GitHub Release を作成して公開する

## 目的と入力

review 済み変更の version tag に対応する GitHub Release を人が作成し、公開します。入力は確認済みの `{{version}}`、リポジトリのタグ規約、対象 PR、確認済みの merge commit SHA、操作を担当する利用者です。

## 手順と判断

1. User Task `P0002-00004-task-01` で人が GitHub の Tags から Draft a new release を選びます。`{{version}}` とタグの規約からタグ名を決め、入力として受け取った merge commit SHA を対象に指定します。Release notes を用意する場合は、対象 PR の差分に沿っているかを確認します。タグ対象の事前照合と Release notes の確認は再利用時の追加案です。記録例では利用者が新しいタグに `v0.4.2` を指定したと報告しました。
2. User Task `P0002-00004-task-02` で人が Publish release を操作し、表示された Release の完了を確認します。AI はユーザーが報告した UI 操作と、独立した API / remote ref の検証結果を区別して記録します。tag と Release object は別の成果物です。

## 出力と完了条件

利用者から公開完了の報告を受けたら、タグ名と Release の参照を親 Process の出力に記録します。公開後に追加確認を行った場合は、その結果を添えます。
