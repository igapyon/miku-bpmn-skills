# P0002-00003 Draft PR を review して merge する

## 目的と入力

Draft PR の変更を人が review し、合意した変更だけを対象 base に merge します。入力は `{{draft_pr_url}}`、published head branch、base branch、PR head SHA、review authority です。

## 手順と判断

1. User Task `P0002-00003-task-01` で人が Draft PR の差分と base を確認し、Ready for Review にします。この User Task は人が ready と判断して Ready for Review にした場合にだけ完了します。変更要求または停止なら Process はここで待ち、merge へ進みません。AI は人の review を代行しません。
2. User Task `P0002-00003-task-02` で人が Merge pull request、続いて Confirm merge を操作します。画面の対象 PR と base が入力に合うことを確認します。対象 PR と操作結果を報告してもらいます。
3. User Task `P0002-00003-task-03` で人がリポジトリの方針に従ってマージ済みの公開ブランチを削除するか保持し、結果を報告します。
4. `P0002-00003-task-04` で GitHub の PR 詳細を読み取り専用で参照し、対象リポジトリ、PR、head SHA、base ブランチ、マージ済みの状態と merge commit SHA を照合します。PR を照合できない場合や SHA を取得できない場合は、確認できなかった情報を示し、揃うまで Release 工程を保留します。

今回の事例では、利用者が PR #8 の Ready for Review、Merge pull request、Confirm merge、Delete branch を操作したと報告しました。merge commit SHA をツールで確認したのは後続の `miku-scm sync pull` です。タスク04は、再利用時に Release のタグ対象を公開前に確かめるための追加案です。

## 出力と完了条件

対象 PR の URL と番号、公開ブランチ、head SHA、base ブランチ、確認済みの merge commit SHA を P0002-00004 と P0002-00005 に渡します。対象 PR がマージ済みで、その merge commit SHA が確認できたら完了です。
