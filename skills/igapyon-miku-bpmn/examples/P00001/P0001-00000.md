# Example P00001 — Agent Skill の新規作成

miku-bpmn 自身の立ち上げを題材に、daybook の activity から見つけた Process を組み合わせ、レビュー済みの Agent Skill 初稿を作る例です。実際の作業記録をもとに、Process の切り出し方、実行時の会話、実行後の報告を再構成しています。

## Activity から見つけた Process

入力は、構想の相談から初稿の修正までを記録した activity です。記録にある次の作業を、別の Agent Skill の立ち上げでも使える単位にまとめました。

| Process | 記録で確認できた作業 |
| --- | --- |
| `P0001-00001` 構想と名前を決める | 生成AIとの作業から見えてきたパターンを題材に、process discovery などの関連概念を調べました。BPMN をモデルの基準にする方針を決め、製品名の候補を比較しました。 |
| `P0001-00002` Agent Skill の初稿を作る | 利用者が GitHub リポジトリを作成して clone し、AI が README、SKILL、TODO の初稿を作りました。合意した出発点と、まだ判断が必要な項目を文書に整理しました。 |
| `P0001-00003` 初稿をレビューして修正する | README と SKILL の記述を照合し、選んだ Process を親の Process に組み立てて提示する手順が SKILL に足りないと分かりました。その後、SKILL に手順を追加しました。 |

## 親の Process の定義

この同梱例では、末尾が `-00000.md` のファイルが親の Process です。`-00001.md` 以降に、親が呼び出す Process の定義を置きます。

この見本では、利用者が `P0001-00001` → `P0001-00002` → `P0001-00003` の順を指定します。次の親の Process を実行前に提示します。

**Agent Skill の初稿を整える**（`P0001-00000`）

```text
Start
  → Call Activity P0001-00001
  → Call Activity P0001-00002
  → Call Activity P0001-00003
  → End
```

| Call Activity | 受け取る入力 | 渡す出力 |
| --- | --- | --- |
| [P0001-00001 構想と名前を決める](P0001-00001.md) | 利用者のアイデアと利用例。この例では、daybook の activity から仕事の手順を見つけ、別の仕事で AI が再利用する場面を想定します。 | 企画、名前、未決事項を `P0001-00002` へ。企画は `P0001-00003` でも参照します。 |
| [P0001-00002 Agent Skill の初稿を作る](P0001-00002.md) | `P0001-00001` の出力と、利用者が指定するローカルの作業先 | README、SKILL、TODO の初稿を `P0001-00003` へ。未決事項は TODO で渡します。 |
| [P0001-00003 初稿をレビューして修正する](P0001-00003.md) | 確認済みの企画と `P0001-00002` の初稿 | レビュー済みの初稿、修正の要約、残る未決事項 |

企画と名前は `P0001-00001-confirm` の回答で確定します。作業先には、利用者が用意した `miku-bpmn-skills` のローカルリポジトリを使います。

`P0001-00003` が完了したら、その出力を親の Process の成果として利用者に返します。

## 実行中の質問と再開

`P0001-00001-confirm` に達したら、AI は質問を示し、初稿を作り始める前に回答を待ちます。以下は同じ会話でのやり取りの例です。

> **AI**　初版では、activity から見つけた Process を利用者が選び、指定した順に実行する案です。この流れは BPMN の親の Process と Call Activity で表せます。この方針で進めてよいですか？ 名前は、BPMN を基準にすることが伝わる **miku-bpmn** と、用途を広く表す **miku-process** のどちらにしますか？
>
> **利用者**　その範囲で進めてください。BPMN をモデルの基準にして、名前は miku-bpmn にします。

AI は回答を `P0001-00001-confirm` に反映し、`miku-bpmn`、`miku-bpmn-skills`、`igapyon-miku-bpmn` の名前と確認済みの企画を使って `P0001-00002` へ進みます。

## 実行後に利用者へ返す内容

**完了**　`P0001-00001`、`P0001-00002`、`P0001-00003` が完了し、レビュー済みの初稿が揃いました。

- `README.md` に目的、BPMN を基準にする方針、利用者が Process と順序を指定する使い方を記載しました。
- `skills/igapyon-miku-bpmn/SKILL.md` に、指定された Process を親の Process から順に呼び、実行前に組み立て結果を提示する手順を追加しました。
- `TODO.md` に、Process 定義の保存形式、初版で扱う BPMN 要素、回答待ちからの再開の検証を残しました。

daybook の activity には、実行した工程、User Task の回答、成果物、残る判断を記録します。この見本なら「BPMN を基準とする方針と miku-bpmn の名前を確認して再開。README、SKILL、TODO の初稿を作成し、レビューで不足していた親の Process の提示手順を SKILL に追加。保存形式と再開の検証は継続」と記録します。

元の活動記録では、レビュー後の初稿は GitHub の PR に反映されました。GitHub Actions で配布用 ZIP を作る案は、その後の検討事項として残りました。
